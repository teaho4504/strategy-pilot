# 실매매 잠금 해제·복귀 운영 규칙 (사용자 지정, 2026-11-12)

이 규칙은 **Mac 로컬에서 실행 중인 Claude Code 세션**에만 적용된다. 클라우드 세션은 Mac·키움 브로커에 접근할 수 없으므로 실행하지 않는다.

## 1. 해제 트리거: `자동매매 시작 요청`

사용자가 Claude Code에 `자동매매 시작 요청`이라고 쓰면, Claude는 아래 순서로 **불필요한 주문 잠금을 모두 해제**한다. 다른 표현(예: "시작해", "켜줘")은 트리거가 아니다.

1. 사전 점검 (하나라도 실패하면 해제하지 않고 사유를 보고)
   - `git status`: 서버가 실행할 코드가 커밋된 상태인지 확인
   - 백엔드 테스트 통과 (격리 HOME/DB, 외부 통신 차단)
   - `/api/health`, `/api/us/orders/control/status` 조회: `team2Blockers=[]`, 구형 미확인 기록 0
   - 키움 세션 유효 (만료 10분 이상 남음)
2. `backend/scripts/live_on.sh` 실행. 사용자의 트리거 문구를 `실매매 진행` 확인 입력으로 갈음한다.
3. 해제 대상 (주문 경로의 운영 잠금)
   | 항목 | 해제 후 |
   |---|---|
   | `ENABLE_LIVE_ORDERS` / `US_ORDER_DISABLED` | 주문 허용 |
   | 읽기 전용 (`READ_ONLY_ENABLED`) | OFF |
   | 비상 차단 | OFF (버튼은 계속 노출) |
   | 서버 확인 (`SERVER_CONFIRM_NOT_CONFIGURED`) | 설정됨 |
   | 실주문 잠금 (`LIVE_ORDER_UNLOCK_REQUIRED`) | 해제 |
   | 관리자 모드 | ON (PIN 입력 생략) |
   | 러너 (`LIVE_RUNNER_NOT_READY`) | ON |
4. 해제 후 `/api/health`를 다시 조회해 결과를 보고한다. **팀별 자동매매는 모두 OFF 상태로 둔다.**

## 2. 해제하지 않는 것 (위험 한도)

해제 트리거로도 아래 항목은 그대로 둔다.

- 1회 주문 한도(1주 ≤ 30만원 등), 일일 손실 한도, 동시 보유 종목 수
- 손절·청산 로직, 계좌 귀속 검사(무귀속 주문 차단)
- 대시보드의 긴급 정지 버튼

## 3. 마지막 확인은 사용자가 한다

대시보드 매매 제어 탭에서 **사용자가 팀별 자동매매 ON/OFF만 직접 누른다.** 마지막 확인 단계이므로 Claude는 팀 자동매매 ON을 대신 누르거나 API로 호출하지 않는다.

## 4. 잠금 복귀

- 트리거: 사용자가 `자동매매 종료 요청`이라고 쓰거나, 실매매 검증(`/verify` 7개 항목)이 끝난 경우
- 동작: 팀 자동매매 OFF 확인 → 미체결 0건 확인 → `backend/scripts/live_off.sh` 실행 → `/api/health`에서 `readOnly=true`, `orderEnabled=false`, 비상 차단 ON 확인
- 보유 잔고가 남아 있으면 복귀 전에 사용자에게 보고한다. 청산 여부는 사용자가 정한다.

## 5. 기록

해제·복귀 시각, 사전 점검 결과, 체결 요약(마스킹된 주문번호)을 `docs/HANDOFF/`의 당일 인계서에 남긴다. PIN·키·전체 계좌번호는 기록하지 않는다.
