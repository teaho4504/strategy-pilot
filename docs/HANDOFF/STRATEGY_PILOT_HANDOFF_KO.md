# Strategy Pilot 프로젝트 인수인계

작성 기준일: 2026-08-22  
대상: Windows 또는 macOS 로컬 환경에서 현재 프로젝트를 안전하게 이어서 개발하는 사용자와 Codex

## 1. 프로젝트 목표

Strategy Pilot은 미국주식 데이터를 키움 REST/WebSocket API로 수집하고, Python 전략 엔진이 조건을 판정하며, Vite React 대시보드에서 계좌·시세·전략·성과를 확인하는 로컬 우선 자동매매 시스템입니다.

현재 가장 중요한 원칙은 다음과 같습니다.

1. 브라우저는 키움에 직접 연결하지 않습니다.
2. App Key, Secret Key, 키움 토큰은 백엔드와 운영체제 보안 저장소 밖으로 노출하지 않습니다.
3. 매매 후보의 유일한 런타임 전략 소스는 키움 HTS 조건검색식입니다.
4. 주문 상태 모델과 사전검사 코드는 존재하지만 실제 주문 네트워크 전송은 구현하지 않고 차단합니다.
5. 주문 요청 성공과 실제 체결을 구분합니다.

## 2. 현재 구성

| 계층 | 구현 기술 | 주요 역할 |
|---|---|---|
| 프론트엔드 | Vite, React, TypeScript, React Router, React Query | 로그인, 계좌, 시세, 전략, 분석, 설정 UI |
| 백엔드 API | Python, FastAPI, Pydantic | 인증, 세션, 계좌/시세 API, 안전 정책, 대시보드 데이터 제공 |
| 키움 연동 | httpx, websockets, keyring, kiwoomcli | 토큰, REST TR, 조건검색, 실시간 시세/호가 |
| 전략 엔진 | Python dataclass와 순수 계산 함수 | HTS 조건 편입 후보, 시세 최신성, 진입/청산 상태 판정 |
| 리스크 | Python + SQLite | 주문 가능 현금, 종목 수, 분할매수, 예약, 복구 상태 |
| 저장소 | SQLite | 시세 이벤트, 전략 판단, 위험 차단, 주문/체결/예약 이력 |
| 테스트 | pytest, Vitest, Testing Library, TypeScript, Vite build | 네트워크 없는 계약/행동 검증 |

## 3. 꼭 필요한 핵심 기능

| 우선순위 | 기능 | 이유 | 현재 상태 |
|---|---|---|---|
| P0 | 안전한 인증/비밀 관리 | 계좌 보호의 기본 경계 | 구현, 키움 토큰 서버 상태에 의존 |
| P0 | 실시간 시세 최신성 검사 | 오래된 가격으로 매매하면 큰 손실 가능 | 구현 |
| P0 | 주문 상태/부분체결/재시작 복구 | 중복 주문과 과매도를 막음 | 부분 검증 |
| P0 | 런타임 잠금과 Kill Switch | 신규 주문을 즉시 차단 | 구현, 항상 기본 잠금 |
| P0 | 계좌 현금·잔고·미체결 대조 | 내부 상태와 실제 계좌 일치 필요 | 구현, 지속 검증 필요 |
| P1 | 조건검색 다종목 감시 | 전략별 여러 후보를 탐색 | 구현 |
| P1 | 전략 계산과 설명 가능한 차단 사유 | 왜 진입하지 않았는지 확인 | 구현 |
| P1 | 자동청산과 실패 경고 | 손절/익절/장마감 리스크 | 부분 구현·실환경 검증 필요 |
| P1 | 백테스트와 비용 반영 | 전략 수익성을 검증 | 기반 구현, 데이터/검증 미완료 |
| P2 | 보안 원격접속 | 모바일 운영 시 공개 노출 방지 | 로컬 도구 구현, VPN/TLS 미완료 |

## 4. 제작 완료 또는 코드가 구현된 기능

### 4.1 CLI 프로필 로그인

```text
로그인 화면
-> PIN으로 프로필 목록 요청
-> FastAPI가 kiwoomcli 설정의 안전한 프로필 정보만 반환
-> 사용자가 프로필 선택
-> 백엔드가 운영체제 보안 저장소에서 키/시크릿 로드
-> 백엔드가 키움 토큰 발급
-> 대시보드용 임시 세션 발급
-> 이후 API에 Bearer 세션 자동 첨부
```

프론트엔드: `src/auth/LoginScreen.tsx`, `src/auth/AuthProvider.tsx`  
백엔드: `backend/app/api/auth.py`, `kiwoom_cli_profile.py`, `token_manager.py`, `kiwoom_session.py`

토큰 API가 HTTPS에서 HTTP로 리다이렉트하면 `TOKEN_ENDPOINT_REDIRECT`로 차단합니다. 리다이렉트를 따라가거나 HTML을 토큰으로 해석하지 않습니다.

### 4.2 계좌와 평가자산

| 데이터 | TR | 백엔드 | 화면 |
|---|---|---|---|
| 예수금 | `ust21110` | US account service와 mapper | Home |
| 통화별 예수금/평가금 | `ust21120` | valuation mapper | Home |
| 보유종목/매도가능수량 | `ust21070` | holdings mapper | Home, 주문 안전검사 |
| 실현손익 | `ust21630` | no-data 처리 포함 | Analytics |
| 기간 수익률 | `ust21650` | 날짜 범위 요청 | Analytics |
| 일별 계좌수익률 | `usa21670` | `from/to` 검증 | Analytics |
| 당일 체결 | `ust21510` | 연속조회 병합 | Analytics, 주문 복구 |

화면은 mock fallback 없이 로딩·빈 결과·오류를 구분해야 합니다.

### 4.3 시세와 차트 백데이터

- 실시간 종목 조회 순위: `usa01980`
- 전일대비 등락률: `usa20910`
- 거래량 상위: `usa20530`
- 가격 급등락: `usa20930`
- 종목 정보/일반주식 검사: `usa10100`
- 분/일/주/월 차트: `usa06011`~`usa06014`

Quotes 화면은 React Query로 랭킹 API를 호출합니다. 차트 UI는 우선순위가 낮지만, 캔들 백데이터는 전략의 EMA/VWAP/ATR 계산에 사용합니다.

### 4.4 조건검색과 실시간 시세

키움 조건식 처리 순서:

```text
usa20280 목록조회
-> usa20281 일반조회
-> usa20290 실시간 등록
-> 편입/이탈 종목 캐시
-> FE/FT 시세·호가 구독
-> 전략별 후보 판정
-> 전략 OFF 또는 세션 종료 시 usa20291 해제
```

FE는 체결가, FT는 호가입니다. 연결 해제 시 지수 백오프로 재연결하고 전체 구독을 다시 등록합니다. 수신 지연과 누락 종목 수를 전략 화면에 표시합니다.

### 4.5 키움 HTS 조건 전략

프로그램 전략 빌더와 프로그램 검색식 런타임은 제거했습니다. 전략 화면은 `usa20280`으로 받은 HTS 저장 조건식을 그대로 나열하고 조건별 ON/OFF 상태를 관리합니다. ON 상태의 조건은 `usa20290` 실시간 편입·이탈 종목을 감시합니다.

조건 편입 종목은 세션, 시세 최신성, 가격 유효성, 중복 후보 및 자금 상태를 확인하는 읽기 전용 진입 관찰 대상으로 사용합니다. 기본 청산 프로필은 상태 모델에서 익절 +2%, 손절 -2%로 계산하지만 실제 매도 주문은 전송하지 않습니다.

EMA/VWAP/ATR 기반 프로그램 전략과 백테스트 계산 모듈은 연구용 코드로만 남아 있으며 대시보드 런타임 전략 목록에는 노출하지 않습니다.

### 4.6 읽기 전용 관찰 러너

관찰 러너 코드는 조건 편입 후보와 상태 판정을 기록할 수 있지만 로컬 기본 실행에서는 비활성입니다.

관찰 모드에서는 다음을 하지 않습니다.

- 주문 사전검사 실행
- 자금 예약
- `ust20000`/`ust20001` 호출
- 자동청산 실행

### 4.7 주문과 리스크 코드

다음 흐름의 코드와 테스트가 존재합니다.

```text
전략 진입 준비
-> 세션/시세/현금/종목/중복/잠금 검사
-> usa10100 일반주식 확인
-> ust31490 주문가능수량 확인
-> ust21070/ust21050/ust21510 대조
-> 자금 예약
-> 주문 전송 경계에서 차단
-> 읽기 전용 F4/F5 및 REST 상태 형상 검증
-> 부분/완전체결/취소/거절 복구 모델 테스트
```

그러나 이 영역은 실환경 종단 검증이 완료된 것으로 간주하면 안 됩니다. 기본 실행 스크립트는 주문을 비활성화하고 런타임 잠금을 유지합니다.

## 5. 대시보드 구조

| 탭 | 주소 | 기능 | 백엔드 연결 |
|---|---|---|---|
| 홈 | `/` | 평가자산, 보유종목, 활성전략 요약 | 계좌/보유 TR |
| 시세 | `/quotes` | 등락률·거래량·급등락 랭킹 | 랭킹 TR |
| 전략 | `/strategies` | HTS 조건식 목록, 조건별 ON/OFF, 현재 편입 종목 | 조건 REST/WebSocket, 전략 상태 API |
| 분석 | `/analytics` | 당일 실현손익, 일별 손익 캘린더, 실제 주문·체결 내역 | `ust21630`, `usa21670`, `ust21510` |

| 주문 | `/orders` | 수동주문 화면 제거 | `/strategies`로 이동 |

## 6. 데이터 저장 방식

- 최신 FE/FT 값: 메모리 캐시
- 실시간 이벤트: SQLite의 `realtime_quote_events`
- 전략 판단: `us_strategy_decisions`
- 조건 편입, 위험 차단, 주문/체결/예약: 각 이벤트/상태 테이블
- 시간: UTC 원본, ET 전략 시간과 미국 거래일, 필요 시 KST 표시

SQLite는 런타임 데이터이므로 Git이나 일반 USB 소스 아카이브에 넣지 않습니다.

## 7. 현재 가장 중요한 문제

1. 현재 폴더에는 Git 메타데이터가 없어 변경 이력과 안전한 롤백 기준을 별도로 복구해야 합니다.
2. 조건검색과 FE/FT는 실수신되지만 한 미국장 세션 전체의 재연결·편입/이탈 장시간 검증이 필요합니다.
3. 주문/부분체결/자동청산은 상태 모델만 존재하며 실제 주문 종단 검증 대상으로 간주하지 않습니다.
4. 백테스트 표본은 500건 기준에 미달해 수익성 주장을 할 수 없습니다.
5. 공개 IP를 통한 직접 모바일 접속은 운영 보안 수준이 아닙니다.

## 8. 개선 로드맵

| 단계 | 작업 | 완료 기준 |
|---|---|---|
| 0 | Git 기준선과 작업 이력 복구 | 별도 복사본에서 동일 테스트 재현 |
| 1 | 조건검색·FE/FT 한 세션 관찰 | 다종목 후보, 재연결, 최신성 검증 |
| 2 | 계좌·손익·체결 TR 대조 | 키움 화면과 일별 값 일치 |
| 3 | 과거 데이터/비용 포함 백테스트 | 최소 표본 충족 및 재현 가능한 성과표 |
| 4 | 읽기 전용 F4/F5·REST 상태머신 검증 | 부분체결/취소/재시작 중복 방지 모델 검증 |
| 5 | 인증·로그·파일 권한 강화 | PIN 제한, 로컬 IP, 감사로그 점검 |
| 6 | VPN/TLS 기반 원격 운영 | 공개 포트 없이 인증/모니터링 완료 |

## 9. 절대 하지 말아야 할 것

- 비밀값, 계좌번호, 토큰, PIN을 코드·문서·테스트·로그에 기록하지 않습니다.
- 프론트엔드에서 키움 API를 직접 호출하지 않습니다.
- 작동시키기 위해 주문 잠금이나 리스크 검사를 임의로 제거하지 않습니다.
- 주문 접수를 체결로 간주하지 않습니다.
- 미확정 주문이 있을 때 다음 주문을 전송하지 않습니다.
- 오래된 시세나 0원 가격으로 주문하지 않습니다.
- 데이터가 없을 때 mock 값으로 대체하지 않습니다.
- `.env`, SQLite, `node_modules`, `dist`, 백업 파일, `pnpm-lock.yaml`을 이동/커밋 대상에 넣지 않습니다.
- 원본 Mac에서 `git clean`, `git reset --hard`를 실행하지 않습니다.
- 백테스트 결과 없이 자동매매 전략을 수익 전략으로 표현하지 않습니다.
- 로컬 Vite/FastAPI를 공개 인터넷에 직접 노출하지 않습니다.

## 10. 새 기기 시작 순서

1. [새 기기 설정 문서](skill/strategy-pilot-maintainer/references/new-device-setup.md)에 따라 Git 이력과 안전한 작업트리 오버레이를 함께 이전합니다.
2. Node/Python 의존성을 새로 설치합니다.
3. 새 환경에서 `kiwoomcli setup`을 다시 실행합니다.
4. read-only/order-disabled 기본값으로 전체 테스트를 실행합니다.
5. 로컬 서버를 시작하고 PIN/프로필/계좌 read-only 호출을 확인합니다.
6. 조건검색과 FE/FT 관찰을 검증한 뒤 다음 개발을 시작합니다.

Codex에는 [Strategy Pilot Maintainer skill](skill/strategy-pilot-maintainer/SKILL.md)을 설치해 사용합니다.
